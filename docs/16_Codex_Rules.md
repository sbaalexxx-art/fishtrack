# AIFishMap Codex Rules

Status: OFFICIAL

Version: 1.0

These rules are mandatory for every task in this repository.

---

# 1. Source of Truth

The Project Bible is the official source of truth.

The approved UI design is the only visual reference.

Never redesign approved UI.

Flutter follows the design.

Never the opposite.

---

# 2. Read Before Coding

Before making any change always read:

00_Project_Bible.md

05_Design_System.md

06_UI_UX.md

15_Current_Sprint.md

17_Design_Status.md

---

# 3. Architecture

Preserve the existing architecture.

Do not move files.

Do not rename files.

Do not change public APIs.

Do not duplicate widgets.

Reuse existing components whenever possible.

---

# 4. Design

Pixel perfect implementation.

Premium quality only.

Glassmorphism must remain elegant.

Respect:

Spacing

Typography

Radius

Colors

Shadows

Blur

Animations

Never replace custom UI with Material defaults.

---

# 5. Flutter

Every task must compile.

flutter analyze must pass.

No new warnings.

No overflow.

No RenderFlex errors.

No placeholder code.

No TODO.

No commented code.

---

# 6. Workflow

Read the target file.

Read dependent files.

Understand before coding.

Modify only requested files.

Never modify unrelated files.

---

# 7. Code Quality

Production ready.

Readable.

Maintainable.

Professional naming.

Use const whenever possible.

Avoid unnecessary rebuilds.

---

# 8. Definition of Done

A task is complete only if:

Flutter analyze passes.

Project builds.

No overflow exists.

Implementation matches approved design.

No unrelated files changed.

---

# 9. Communication

Never guess.

If information is missing, ask.

Never redesign approved UI.

Never surprise the developer.

---

# 10. AIFishMap Principle

Quality over speed.

Design first.

Flutter second.

Premium always.
