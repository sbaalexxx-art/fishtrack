# AIFishMap Design System

---

# Purpose

The Design System defines the visual language of AIFishMap.

Every screen, widget and component must follow these rules.

Consistency is more important than creativity.

---

# Design Philosophy

The interface must feel:

- Premium
- Clean
- Modern
- Minimal
- Professional

The application should never feel overloaded.

Every element must have a purpose.

---

# Theme

Dark Theme is the default.

The interface is optimized for outdoor use and night fishing.

---

# Color Palette

## Primary

Blue

Used for:

- Primary actions
- Active navigation
- Important highlights

---

## Secondary

Green

Used for:

- Positive indicators
- Fishing conditions
- Success states

---

## Warning

Orange

Used for:

- Weather alerts
- Warnings
- Attention indicators

---

## Error

Red

Used only for:

- Errors
- Dangerous actions

---

## Background

Very dark grey / almost black.

Cards use a lighter dark shade.

---

# Typography

Hierarchy must always be respected.

## Large Title

Screen titles.

---

## Card Title

Widget titles.

---

## Body

Main information.

---

## Caption

Secondary information.

---

# Spacing

Use consistent spacing.

Small

8 px

Medium

16 px

Large

24 px

Extra Large

32 px

Avoid random spacing values.

---

# Border Radius

Cards

16–20 px

Buttons

12–16 px

Navigation

Rounded premium appearance.

---

# Icons

Use Material Symbols whenever possible.

Icons should communicate meaning immediately.

---

# Cards

Cards should:

- Have rounded corners
- Use subtle elevation
- Maintain equal spacing
- Contain only essential information

No unnecessary decorations.

---

# Buttons

Buttons must have:

- Clear hierarchy
- Large touch area
- Consistent padding

---

# Navigation

Bottom Navigation follows the approved Home Premium mockup.

It must remain identical throughout the application.

---

# Maps

OpenStreetMap is the visual centerpiece of AIFishMap.

The map should always receive the highest visual priority.

---

# Animations

Animations must:

- Feel smooth
- Improve usability
- Never delay interaction

Purpose is more important than visual effects.

---

# Responsive Design

Layouts must adapt automatically.

No screen should depend on fixed dimensions.

The application should work correctly on:

- Small phones
- Large phones
- Tablets

---

# Official Rule

If a new component does not match the Design System, the Design System is updated before implementation.

---

# End of Design System
