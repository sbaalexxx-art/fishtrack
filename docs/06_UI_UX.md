# AIFishMap UI / UX Guidelines

---

# Purpose

This document defines the official User Interface (UI) and User Experience (UX) principles of AIFishMap.

Every new screen, widget and interaction must follow these guidelines.

---

# Design Philosophy

The interface must feel:

- Premium
- Modern
- Fast
- Clean
- Professional

The application is built for anglers who need information quickly, even outdoors.

---

# User Experience Principles

Every interaction should answer one question:

"Does this help the angler?"

If the answer is no, the feature should be simplified or removed.

---

# Navigation

Navigation must always be simple.

The user should never be more than two taps away from important information.

---

# Home Screen

The Home screen is the heart of AIFishMap.

Priority:

1. Header
2. Interactive Map
3. Dashboard
4. Recent Catches
5. Bottom Navigation

---

# Header

Contains:

- Greeting
- Current location
- Notifications (future)
- Profile shortcut

Must remain clean and compact.

---

# Map

The map is the main element of the application.

Requirements:

- OpenStreetMap
- Fast loading
- Smooth zoom
- User location
- Fishing stations
- Future overlays

The map should always receive the highest visual priority.

---

# Dashboard

The dashboard provides an instant overview.

Approved cards:

- Water Level
- Weather
- Community
- Fishing Conditions (AI)

Cards must:

- be compact
- use consistent spacing
- follow the Design System
- avoid unnecessary text

---

# Recent Catches

Displays recent community catches.

Each item should contain:

- Species
- Weight
- Location
- Image indicator
- User (future)

---

# Bottom Navigation

The approved navigation contains:

- Home
- Map
- Add Catch (center action)
- Reports
- Profile

The navigation style must remain consistent throughout the application.

---

# Future Screens

Every future screen must follow the same principles:

- consistency
- simplicity
- speed
- readability

---

# Responsive Behaviour

The application must adapt automatically to:

- Small phones
- Large phones
- Tablets

No layout should rely on fixed screen dimensions.

Scrolling should only be used when content genuinely exceeds the available space.

---

# Accessibility

Buttons must be easy to press.

Text should remain readable in daylight.

Icons should always have a clear meaning.

---

# Official Rule

UI changes require approval before implementation.

Approved designs become part of the Project Bible.

---

# End of UI / UX Guidelines
